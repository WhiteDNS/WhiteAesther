# راهنمای Aether 2.3 در دسکتاپ

این راهنما برای تغییرات آمادهٔ انتشار دسکتاپ است؛ شمارهٔ نسخهٔ اندروید، شمارهٔ نسخهٔ دسکتاپ نیست.

## کجا تنظیم کنیم؟

از **Advanced → Routes & transports → TLS and ECH** استفاده کنید. تنظیمات این بخش روی
Aether، از جمله مرحلهٔ Aether در زنجیرهٔ carrier و درخواست ثبت‌نام WARP اثر دارند؛ TLS داخلی
Psiphon و Tor با این کادرها تغییر نمی‌کند. برای مقایسهٔ یک روش مشخص، carrier را روی Manual
و Aether بگذارید و Protocol را مشخص کنید. هر بار یک گزینه را تغییر دهید و دوباره وصل شوید.

## گزینه‌ها و پیش‌فرض‌ها

| گزینه | قالب و کاربرد |
|---|---|
| TLS 1.2 cipher suites | نام‌های BoringSSL با جداکنندهٔ `:`؛ نمونه `ECDHE-RSA-AES128-GCM-SHA256`. خالی یعنی پیش‌فرض هسته. این گزینه رمزهای TLS 1.3 را تعیین نمی‌کند؛ H3 فقط TLS 1.3 دارد. |
| TLS groups | گروه‌های تبادل کلید به ترتیب دلخواه، با جداکنندهٔ `:`؛ نمونه `X25519:P-256:P-384`. خالی یعنی پیش‌فرض هسته. |
| Disable GREASE | پیش‌فرض خاموش است، یعنی GREASE فعال می‌ماند. برای آزمایش سازگاری handshake تغییر دهید؛ بررسی گواهی و رمزگذاری خاموش نمی‌شوند. |
| WARP registration address | نام میزبان یا IP، با پورت اختیاری؛ پیش‌فرض پورت ۴۴۳. مقصد شبکهٔ ثبت‌نام تغییر می‌کند و Host/SNI و بررسی گواهی حفظ می‌شوند. URL یا مسیر سایت وارد نکنید. با Endpoint تونل فرق دارد. |
| Encrypted Client Hello | خالی یا `off`: خاموش؛ `auto`: دریافت خودکار کلید؛ base64: کلید دستی ECHConfigList. مقدار قدیمی `require` همچنان پذیرفته می‌شود و مانند `auto` بدون ECH معتبر ادامه نمی‌دهد. |
| ECH resolver | `udp://IP[:port]`، `tcp://IP[:port]` یا DoH با `https://`. پورت DNS پیش‌فرض ۵۳ و DoH پیش‌فرض ۴۴۳ است. مقدار خالی در دسکتاپ از `https://1.1.1.1/dns-query` استفاده می‌کند. |
| ECH key domain | دامنهٔ رکورد HTTPS حامل کلید؛ پیش‌فرض هسته `cloudflare-ech.com`. |

`203.0.113.10:443` فقط نمونهٔ قالب آدرس ثبت‌نام است و سرور قابل اتصال نیست.
Resolver بالا فقط کلید ECH را دریافت می‌کند و DNS ترافیک برنامه‌ها را عوض نمی‌کند. DoH از
upstream/carrier فعال عبور می‌کند و برای H2 پشت carrierهای TCP به UDP پورت ۵۳ وابسته نیست.
UDP به پشتیبانی واقعی datagram در upstream نیاز دارد؛ برای carrierهای TCP از DoH یا TCP
استفاده کنید. DoH هسته همچنین overrideهای `@address=host` و `@sni=name` را می‌پذیرد.

ECH روی H2 و H3، ثبت‌نام WARP و مرحلهٔ بیرونی WireGuard over MASQUE اعمال می‌شود. تلاش
درخواست‌شدهٔ ECH بدون کلید قابل ارائه یا پذیرش سرور، نام سرور را بی‌صدا بدون ECH نمی‌فرستد.
حالت Automatic ممکن است تلاش دیگری انتخاب کند، از جمله روشی بدون ECH؛ الزام یک تلاش را
با الزام همهٔ carrierهای Automatic اشتباه نگیرید. برای الزام مسیر دستی، Automatic را خاموش
و پروتکل و ECH را مشخص کنید. خاموش‌کردن ECH متن resolver/domain را حفظ می‌کند ولی آن‌ها
را در تلاش خاموش فعال نمی‌کند. شکست ECH مسیر fallback ثبت‌نام بدون ECH نیست.

مقدار نامعتبر هنگام Save یا اتصال خطا می‌دهد؛ متن واردشده در رابط باقی می‌ماند تا اصلاح کنید.
اگر هستهٔ سفارشی قدیمی انتخاب کرده‌اید، **Core executable** را خالی کنید تا از هستهٔ بسته‌بندی‌شده
استفاده شود. Command preview گزینه‌های واقعی را نشان می‌دهد؛ اطلاعات حساس upstream در
environment منتقل می‌شوند و در پیش‌نمایش فرمان قرار نمی‌گیرند.

## Automatic، Discovery و روش‌های تودرتو

Automatic علاوه بر روش‌های قبلی، H2+ECH را هم امتحان می‌کند و ترکیب framing، fragmentation
و ECH برنده را به نشست بعدی می‌دهد. حافظهٔ برنامه برای هر شبکه با تاریخچهٔ هشت گیت‌وی موفق
هسته دو لایهٔ جدا هستند. گیت‌وی ذخیره‌شده پیش از استفاده دوباره اعتبارسنجی می‌شود؛ اطلاعات
قدیمی نیز فرصت یک validation را دارند. تنظیمات TLS در proof جدید هسته لحاظ می‌شوند.

در **Search depth**، گزینهٔ **Verified edges** گیت‌وی‌های شناخته‌شده را در اولویت می‌گذارد و
مسیر را آزمایش می‌کند؛ فهرست تاریخی تضمین دسترسی یا اندازه‌گیری زنده نیست. حالت Stealth
قبلی همچنان جست‌وجوی کم‌همزمانی دارد. scanner تنظیمات TLS/ECH، ثبت‌نام، fragmentation و
upstream نشست را دریافت می‌کند؛ پروتکل گزارش گیت‌وی‌ها همچنان MASQUE است.

**WireGuard over MASQUE**، WireGuard درون MASQUE است و هسته با `--wg-over-masque`
اجرا می‌شود؛ framing بیرونی H2 یا H3 انتخاب‌پذیر است. این روش با **WARP in WARP** (دو
مرحلهٔ WireGuard) و **MASQUE in MASQUE** فرق دارد. پروفایل‌های قدیمی `gool` و `mim` و
هویت هر مرحله حفظ می‌شوند. carrier جلویی که UDP ندارد، مرحلهٔ بیرونی Aether را روی H2
می‌برد تا مقصد مستقیم از شبکهٔ محلی dial نشود.

## ذخیره‌سازی و ارتقا

فیلدها از state فوری رابط خوانده می‌شوند. پاسخ Save فقط متعلق به پیش‌نویس ارسال‌شده است؛
ویرایش تازه‌ای که هنگام انتظار انجام می‌دهید بازنویسی نمی‌شود. برای ماندگاری ویرایش تازه، دوباره
Save کنید. درخواست‌های ذخیره‌سازی به ترتیب اجرا می‌شوند. Restart آخرین Save موفق را می‌خواند.
پروفایل‌های قدیمی برای فیلدهای جدید مقدار خالی و GREASE فعال دریافت می‌کنند.

پیش از حذف یا نصب مجدد، از **Identity → Save a backup** خروجی بگیرید؛ حذف برنامه می‌تواند
هویت موجود را حذف کند و ثبت هویت تازه محدود است. Backup برای تولید داده هویت تازه ثبت
نمی‌کند. فایل پشتیبان شامل کلیدهای خصوصی است؛ آن را مانند گذرواژه نگه دارید. برای Import
ابتدا Disconnect کنید. فرمت بکاپ قبلی حفظ شده است.

تست‌های محلی TLS/DNS و رابط، اثبات اتصال روی شبکهٔ فیلترشده نیستند. برای آزمایش شبکهٔ خود،
Connect، Disconnect/Reconnect، Automatic، H2/H3+ECH و WOM را جداگانه با data check روشن
بررسی کنید. نتیجه و تنظیمات را با Report ثبت کنید؛ گزارش حضور overrideها را نشان می‌دهد و
مقادیر آن‌ها و اطلاعات ورود را افشا نمی‌کند.
